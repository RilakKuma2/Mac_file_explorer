# 릴리즈 배포

0.1.2부터 앱은 GitHub Releases를 직접 확인합니다. `releases/latest`의 태그가 설치된 버전보다 높으면 변경사항을 보여 주고, 사용자가 **업데이트**를 누르면 해당 릴리즈의 DMG를 내려받아 → 코드 서명 확인 → 앱 교체 → 재실행을 진행합니다. 기본 확인 주기는 하루이며, 앱 메뉴에서 수동 확인 또는 자동 확인 해제가 가능합니다.

0.1.1 이하 설치본은 Sparkle로 `appcast.xml`을 읽습니다. 이 사용자들이 새 방식으로 넘어올 수 있도록 **당분간은 `appcast.xml`과 서명된 ZIP도 함께 올립니다.** 0.1.1 이하에서 업데이트하면 새 방식을 쓰는 버전이 설치되고, 그 뒤로는 DMG만 사용합니다.

## 새 버전 올리기

1. `Resources/Info.plist`의 표시 버전과 내부 빌드 번호를 올립니다. 내부 빌드 번호는 표시 버전과 별개로 항상 증가시킵니다(기존 Sparkle 설치본이 이 번호로 비교합니다).
2. `swift test`를 실행하고 변경 사항을 커밋·푸시합니다.
3. 서명 키가 저장된 Mac에서 `./scripts/prepare-release.sh`를 실행합니다.
4. GitHub에서 해당 커밋으로 **일반 릴리즈**를 만듭니다. 태그는 `v0.1.2`처럼 앱 버전과 일치해야 합니다.
5. `dist/releases/v<버전>/`의 **DMG, 업데이트용 ZIP, `appcast.xml`을 함께** 첨부하고 Latest로 지정합니다.

### 새 업데이트 방식이 요구하는 것

- 태그는 `v` + 숫자 버전(`v0.1.2`)이어야 합니다. 숫자가 아닌 태그는 무시됩니다.
- DMG 이름은 `Mac-Explorer-<버전>-<아키텍처>.dmg` 형식이어야 하고(스크립트가 이 이름으로 만듭니다), DMG 안의 앱은 번들 식별자가 같고 버전이 더 높아야 합니다.
- **DMG 안의 앱은 기존 설치본과 같은 인증서로 서명되어 있어야 합니다.** 다르면 앱이 설치를 거부합니다. 로컬 서명 키체인(`~/Library/Application Support/Mac Explorer/Signing`)을 잃으면 기존 사용자는 수동으로 다시 설치해야 하므로 반드시 백업하세요.
- 릴리즈 본문에서 `## 개선 및 수정`, `## 변경사항`, `## 수정사항`, `## Changes` 제목 아래의 내용만 업데이트 창에 표시됩니다. 설치 안내는 다른 제목 아래에 적으세요. 여러 버전을 건너뛴 사용자에게는 그 사이 모든 버전의 변경사항이 최신순으로 표시됩니다.
- 초안·프리릴리즈는 업데이트 대상이 아닙니다.

릴리즈 전에 별도 앱 사본으로 이전 버전 → 새 버전 업데이트를 확인하세요. 빌드는 실행한 Mac의 아키텍처를 대상으로 합니다. 현재 배포 준비 환경은 Apple Silicon(`arm64`)입니다.

## 기존(Sparkle) 채널 유지

- `prepare-release.sh`는 Sparkle 명령줄 도구로 ZIP에 서명하고 `appcast.xml`을 만듭니다. 앱에는 더 이상 Sparkle이 들어가지 않으며, 도구는 필요할 때 `.build/sparkle-tools`로 내려받습니다(`SPARKLE_TOOLS`로 위치 지정 가능).
- 업데이트용 Ed25519 개인 키는 macOS 키체인의 `app.macexplorer.filemanager` 계정에 있습니다. 공개 키(`SUPublicEDKey`)와 `SUFeedURL`은 기존 설치본과의 호환을 위해 `Info.plist`에 남겨 둡니다.
- 서명된 XML이나 ZIP은 생성 후 편집하지 마세요. 키를 Git, 릴리즈 첨부 파일, 로그에 올리지 마세요.
- 0.1.1 이하 사용자가 충분히 줄어들면 `appcast.xml`·ZIP 생성과 `Info.plist`의 `SU*` 키를 제거할 수 있습니다. 단, 마지막으로 올린 `appcast.xml`은 `releases/latest/download/appcast.xml` 주소로 계속 받을 수 있어야 하므로, 제거 후에도 최신 릴리즈에 마지막 appcast를 첨부해 두는 편이 안전합니다.

## 서명과 Gatekeeper

기본 빌드는 로컬 자체 서명입니다. 공개 배포의 Gatekeeper·공증은 업데이트 서명과 별개이며, Developer ID 서명과 공증은 별도로 구성해야 합니다.
